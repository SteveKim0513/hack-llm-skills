# criteria-gap-audit: 기준 공백 측정

세션 하나를 되짚는 `criteria-gap`을 여러 세션으로 넓혀, 공백이 **얼마나** 되는지 잰다.
이 스킬은 "좋다/나쁘다" 기준선을 갖고 있지 않다. 판정 기준은 쓰는 사람이 자기 기록에 직접 표시하면서 만든다. 특정 사람의 기록에서 나온 숫자를 기준선으로 박지 않는다.

## 전제
- 세션 기록의 위치와 형식은 도구마다 다르다. 읽기 전에 `references/claude.md`, `references/codex.md`를 본다.
- **결과 파일에는 대화 원문이 들어간다.** 기본 저장 위치는 `~/.criteria/audit/`이고, 공개 저장소 안에는 저장하지 않는다. 사용자가 다른 곳을 지정하면 그곳에 쓰되, 저장소 안이면 먼저 경고한다.
- 판정과 리포트는 사용자가 한 일이다. 사용자 대신 "공백이다/아니다"를 확정하지 않는다.

## 절차

### 1. 범위 정하기
묻는 건 둘뿐이다. 나머지는 기본값으로 진행한다.
- 어느 도구의 기록을 볼지 (기본: 로컬에서 찾은 모두)
- 기간 (기본: 제한 없음. 비교용 리포트면 기간을 맞춘다)

### 2. 추출
`scripts/extract_sessions.py`로 사람이 쓴 발화와 AI 응답만 뽑는다. 서브에이전트 기록, 도구가 끼워 넣은 알림, 다른 도구에서 가져온 사본, 사용자 발화가 너무 적은 세션은 자동으로 빠진다.
```bash
python3 scripts/extract_sessions.py --stats-only              # 규모만 보기
python3 scripts/extract_sessions.py --sample 25 --out ~/.criteria/audit/sample.jsonl
```
- 먼저 `--stats-only`로 남은 세션 수와 프로젝트별 분포를 사용자에게 한 줄로 알린다.
- **기준을 만드는 단계**의 표본은 직접 표시할 수 있는 크기로 작게, 프로젝트·도구가 골고루 섞이게 한다(스크립트의 `--sample`이 이렇게 뽑는다). 한 프로젝트가 대부분이면 그 사실을 알린다.
- **측정 단계**는 표본 없이 전체, 또는 기간으로 자른다.

### 3. 위임 지점 찾기
세션마다 **사용자가 판단을 AI에 맡긴 지점**을 찾는다. 표현 목록으로 찾지 말고 뜻으로 찾는다: 무엇을 남길지, 어떤 게 좋은지, 어디까지 할지를 AI가 정하게 둔 요청이다. 어떤 언어로 쓰였어도 같다.
각 지점에 기록한다.
- 근거 인용(사용자 발화 짧게). **인용할 수 없으면 버린다.**
- 사용자가 그 요청 안이나 앞에서 기준을 말했는지: `말함` / `안 말함`
- 공백 유형 (`criteria-gap`의 5개): 선별 기준, 품질 기준, 독자와 목적, 제약, 완료 정의
- 이어진 사용자 발화가 결과를 되돌리거나 고치는 말인지: `되돌림` / `이어감` / `끝남`

이 단계의 `말함/안 말함`은 AI의 추정이다. 사용자 판정이 붙기 전까지 `추정`으로 표시한다.

### 4. 사용자가 표본에 판정하기 (기준 만들기)
위임 지점을 **한 번에 하나씩** 보여 주고 사용자가 판정한다. 인용된 요청과 AI가 낸 결과의 한 줄 요약만 보여 주고, AI의 추정 판정이나 암묵 기준은 먼저 보여 주지 않는다(앵커링 방지).
판정 선택지:
- `공백`: 기준이 있었어야 하는데 없었다
- `공백 아님`: 기준 없이 맡겨도 되는 일이었다, 또는 기준을 이미 말했다
- `모르겠음`
공백이면 `영향` 한 단계(큰 / 보통 / 사소)와, 판정 이유 한 줄을 받는다. 이유를 못 쓰면 비워 둔다.

표시할 지점은 한 번에 많아지지 않게 정한다. 사용자가 지치면 멈추고, 그때까지의 판정으로 진행한다. 판정 개수가 적으면 리포트에 그 사실을 쓴다.

### 5. 판정 기준 정리
판정과 이유를 모아 **이 사용자의 공백 판정 기준**을 문장으로 정리한다. 예: "결과물이 외부에 나가는 일은 사소해도 공백", "초안 단계의 탐색은 공백 아님". 이 예시는 형식을 보이는 것이고, 실제 내용은 사용자의 이유에서만 뽑는다.
- 이유가 두 번 이상 반복된 것만 기준 후보로 올린다. 한 번 나온 건 "사례"로 남긴다.
- 정리본을 보여 주고 사용자가 고친 뒤 확정한다. 확정 전에는 초안으로 `~/.criteria/audit/rubric.md`에 저장한다.
- 사용자가 원하면 `criteria` 스킬의 저장 전 점검을 거쳐 기록소에도 저장한다.

### 6. 전체 측정
확정한 판정 기준과 사용자의 판정 예시로 나머지 세션의 위임 지점을 판정한다. 이 단계는 AI의 판정이므로 반드시 **일치율**을 같이 낸다.
- 사용자가 표시하지 않은 지점 중 일부를 무작위로 뽑아 사용자에게 확인받고, AI 판정과 사용자 판정이 얼마나 같았는지 센다.
- 일치율이 낮으면 숫자를 쓰지 않고 5단계로 돌아가 기준을 고친다.
- 세션이 많아 직접 다 읽기 어려우면 세션 묶음 단위로 나눠 병렬로 판정해도 된다. 같은 판정 기준과 예시를 모두에게 준다.

### 7. 리포트
`~/.criteria/audit/report-<날짜>.md`에 저장하고, 대화에는 첫 줄에 결론, 이어서 아래 숫자를 보여 준다. 숫자마다 **분모와 표본 크기**를 같이 쓴다.
- 위임 지점 수, 그중 공백 수와 비율
- 공백 유형별 분포
- 영향 `큰` 공백의 수와 대표 사례 인용 2~3개
- `되돌림` 비율을 공백인 지점과 아닌 지점으로 나눠서. 공백이 실제 손해로 이어졌는지 보는 신호다.
- 판정 출처: 사용자 판정 N건, AI 판정 M건, 일치율
- 이전 리포트가 있으면 같은 판정 기준·같은 기간 길이일 때만 비교한다. 다르면 비교하지 않고 이유를 쓴다.

## 하지 않는 것
- "공백 N% 이상이면 나쁨" 같은 기준선을 제시하지 않는다. 비교는 사용자 자신의 이전 결과와만 한다.
- 근거 인용이 없는 위임 지점을 세지 않는다.
- AI의 추정 판정을 사용자 판정처럼 섞어 세지 않는다. 출처를 나눠 쓴다.
- 표본이 작은데 정확한 숫자처럼 쓰지 않는다. 표본 크기를 옆에 쓰고 "참고용"이라고 밝힌다.
- 결과 파일이나 리포트를 공개 저장소에 넣지 않는다.
