# session-profile: AI 활용 능력 진단

AI와 일할 때 필요한 여섯 능력을 재고, **그중 무엇을 먼저 채워야 하는지와 어떻게 연습할지**를 알려 준다.

| 능력 | 한 줄 정의 |
|---|---|
| 이해 | AI와 정한 결정과 그 결과로 생긴 지금의 상태를 정확히 안다 |
| 읽기 | AI의 긴 답변에서 결론, 경고, 나에게 던진 질문을 놓치지 않는다 |
| 목표 명확성 | 왜 하는지, 끝나면 무엇이 달라져야 하는지 정해져 있다 |
| 원하는 것의 분명함 | 좋은 결과를 가를 자기 기준이 있다 |
| 표현 정확성 | 원하는 것을 받는 쪽이 오해 없이 알게 쓴다 |
| 검증 | AI가 낸 결과와 주장을 받아들이기 전에 맞는지 확인한다 |

정의, 로그 신호, 과제, 채점 기준, 연습법은 `references/abilities.md`, 일꾼 지시문은 `references/tasks.md`, 이해 퀴즈의 문항 규칙은 `references/quiz.md`에 있다. 이 방식을 정한 근거와 시험 결과는 `references/validation-notes.md`, 선행 연구는 `references/prior-work.md`, 앞으로 바꿀 설계는 `references/design.md`.

## 원칙
- **증거는 두 갈래다.** 실제 작업 기록(로그)과, 지금 직접 푸는 짧은 과제. 로그는 그 분야를 아는지, 피곤했는지, AI가 잘 답했는지에 흔들려서 과제로 한 번 더 확인한다.
- **사용자가 하는 일은 과제를 푸는 것 하나뿐이다.** 장면 분류, 과제 검증, 채점, 종합은 AI가 한다. 사용자에게 분류나 채점을 확인받거나 자기 평가를 묻지 않는다. 자기를 어떻게 보고 싶은지가 섞이기 때문이다.
- **과제 화면에는 무엇을 재는지 드러내지 않는다.** 능력 이름이나 채점 기준을 보여 주지 않고, AI에게 첫 메시지 보내기나 답장 쓰기처럼 평소에 할 법한 행동을 시킨다. 무엇을 재는지 알면 실제로는 하지 않는 행동도 모범 답안으로 쓸 수 있다.
- **결과는 한 사람 안에서 능력끼리 견준 것이다.** 다른 사람과 비교하는 점수나 기준선은 만들지 않는다. 근거가 없다.
- **끊김은 원인이 사용자 쪽이라는 근거가 있을 때만 센다.** AI가 잘못한 장면을 사용자의 약점으로 세지 않는다. "네", "진행해" 같은 승인 한마디는 어느 쪽으로도 세지 않는다.
- **서로 독립된 에이전트(서브에이전트) 여럿이 필요하다.** 과제를 만든 쪽이 채점까지 하면 검증이 무의미해진다. 그런 기능이 없는 환경이면 결과에 "검증 안 됨"을 붙인다.

## 전제
- 세션 기록의 위치와 형식은 도구마다 다르다. 읽기 전에 `references/claude.md`, `references/codex.md`를 본다.
- **중간 파일과 결과에는 대화 원문이 들어간다.** 기본 작업 폴더는 `~/.criteria/audit/`이고 공개 저장소 안에는 저장하지 않는다. 대화에 비밀번호나 키가 있으면 과제, 인용, 결과 어디에도 옮기지 않는다.
- 저장소를 확인할 때는 읽기만 한다. 고치거나 실행하지 않는다.
- **결과는 평가받는 사람 한 명에게만 준다.** 기록이 그 사람의 컴퓨터에 있으니 그 사람이 직접 돌린다. 진단을 권한 사람(팀장, 교육 담당)이 있어도 결과 화면은 평가받는 사람에게 건네고, 다른 사람에게 보여 줄지는 그 사람이 정한다. 선발이나 인사 평가에 쓰지 않는다. 판정의 오류율(`abilities.md` 종합 규칙)이 그런 용도를 감당하지 못한다.

## 순서
진행 중에는 지금 어느 단계인지 한 줄씩만 알린다. 중간 결과는 보여 주지 않는다.

### 1. 범위 (한 번만 묻는다)
볼 도구, 로그 기간(기본 최근 30일), 과제에 드는 시간(15~20분)을 한 메시지로 알리고 묻는다. 답이 없으면 기본값으로 간다.

### 2. 추출
```bash
python3 scripts/extract_sessions.py --stats-only
python3 scripts/extract_sessions.py --since <날짜> --max-chars 3000 --out ~/.criteria/audit/sessions.jsonl
```
서브에이전트 기록, 도구가 끼워 넣은 알림, 다른 도구에서 가져온 사본, 같은 세션의 중복 파일, 사용자 발화가 너무 적은 세션이 빠진다. 지금 진행 중인 대화는 뺀다.

같은 세션의 에피소드 표도 만든다. 사람 요청 하나마다 그 뒤에 일이 어떻게 흘렀는지(도구 오류, 중단, 같은 파일 다시 고침, 다음 요청의 정정 신호, 작업 시간, 읽는 시간)를 숫자로 남긴다. 대화 원문은 없다.
```bash
python3 scripts/episodes.py --sessions ~/.criteria/audit/sessions.jsonl --out ~/.criteria/audit/episodes.jsonl
```

### 3. 기회 찾기와 비용
`tasks.md`의 L1대로 분류자 A가 전체를, 독립된 분류자 B가 30%(최소 8개 세션)를 다시 본다. 사용자 요청마다 능력별로 그 능력을 쓸 기회였는지, 기회였으면 보임/끊김/없음 중 무엇인지 고른다. L2대로 모든 끊김을 다른 일꾼이 다시 따져 원인이 분명히 사용자인 것만 남긴다. 집계와 비용은 스크립트로 한다.
```bash
python3 scripts/log_signals.py --sessions ~/.criteria/audit/sessions.jsonl --events events.jsonl --critic critic.jsonl \
  --events-b events-b.json --out ~/.criteria/audit/signals.json
python3 scripts/estimate.py --events events.jsonl --critic critic.jsonl --episodes ~/.criteria/audit/episodes.jsonl \
  --out ~/.criteria/audit/estimate.json
```
`signals.json`에는 능력마다 기회, 보임, 끊김 수와 두 분류자의 일치(세션 단위 카파와 AC1, 요청 단위 기회 겹침과 결과 AC1)가 나온다. `estimate.json`에는 능력마다 0~100 점수와 구간, 끊김이 만든 다시 작업(요청 100개당 횟수와 분, 구간), 가장 비싼 습관이 나온다(`abilities.md` 비용 규칙). 어떤 능력의 결과 AC1이 0.4보다 낮으면 갈린 요청을 보고 정의를 구체적으로 적어 그 능력만 한 번 다시 분류한다. 그래도 낮으면 결과에 "불안정"으로 적는다.

### 4. 과제 만들기
`tasks.md`의 T1~T6대로 만들고 각 과제의 검증까지 마친다. 기본은 능력마다 과제 하나이고, 합쳐서 15~20분 안에 맞춘다. 로그 증거가 이미 많은 능력은 과제를 빼고 증거가 가장 적은 능력에 하나 더 낸다(`tasks.md` "과제 묶음과 시간").
- 이해 퀴즈 3~4문항 (짧게 승인하고 넘어간 지점에서 그 결정으로 생긴 지금의 환경을 묻는다. `pick_points.py`, `quiz_check.py`)
- 읽기: 새로 지어낸 AI 답변을 읽고, 지문이 사라진 뒤 답장과 동료에게 전하는 글을 쓴다 (읽기)
- 첫 메시지 쓰기: 모호한 상황을 주고 AI에게 보낼 첫 메시지를 쓰게 한다 (목표 명확성)
- 둘 중 하나 쓰기: 고르고, 다른 쪽을 고쳐 달라는 요청을 쓴다 (원하는 것의 분명함)
- 지시 전달 과제 (표현 정확성)
- 작업 보고 받기: AI가 끝냈다고 보낸 보고에 답장을 쓴다. 보고에는 보고만 읽어도 알 수 있는 문제가 섞여 있다 (검증)

괄호 안의 능력 이름은 화면에 나오지 않는다. 만든 과제는 `tasks.md`의 V1대로 다른 일꾼이 검증하고, "과제 파일 조립"대로 ID를 중립적으로 바꿔 한 파일로 묶는다. 능력이 이어 붙지 않게 섞고, 기억이 필요한 이해 퀴즈는 마지막에 둔다. 지난 진단에서 낸 퀴즈 주제는 다시 내지 않는다.

### 5. 과제 풀기 (사용자가 하는 유일한 단계)
```bash
python3 scripts/task_server.py --items ~/.criteria/audit/tasks.json --answers ~/.criteria/audit/answers.json
```
127.0.0.1에서만 열린다. 화면에는 능력 이름과 채점 기준이 나오지 않는다. 읽기 과제는 "다 읽었어요"를 누르면 지문이 사라지고 질문이 나온다. 지시 전달 과제의 명세는 복사하지 말고 자기 말로 쓰도록 안내돼 있다. 채점 기준은 화면에 나오지 않는다. 열어 주고 "다 풀면 제출을 눌러 주세요" 한 줄만 쓴 뒤 제출을 기다린다. 사용자가 과제의 의도를 물으면 형식(지난 대화를 묻는 문항인지, 지어낸 상황인지, 평소처럼 쓰면 된다는 것)만 알려 주고, 무엇을 재는지는 결과에서 알려 준다고 답한다. 로그 분석 결과도 과제를 다 풀기 전에는 보여 주지 않는다.

### 6. 채점
`tasks.md`의 X1(지시 전달 실행)과 G1(채점)대로 한다. 채점자 둘이 따로 채점하고, 다른 문항은 셋째가 정한다. 이해 퀴즈에서 틀림·부분·확신 오답은 이후 세션과 저장소로 사실 확인한다. 사용자가 알고 있는 것과 지금 시스템 동작이 다르다고 확인되면 "생각과 실제가 다른 곳"으로 따로 모은다.

### 7. 종합과 결과
`tasks.md`의 S1대로 `final.json`을 쓰고 한 장짜리 결과를 만든다. 형식은 `references/sample-final.json`(지어낸 샘플)을 따른다.
```bash
python3 scripts/build_final.py --input ~/.criteria/audit/final.json --estimate ~/.criteria/audit/estimate.json \
  --out ~/.criteria/audit/final-<날짜>.html
```
능력별 판정은 스크립트가 `abilities.md`의 종합 규칙대로 계산한다. 순위를 쓰지 않고, 그 사람의 다른 능력 평균과의 차이가 측정의 흔들림을 넘을 때만 **먼저 보완**이나 **강점**을 붙인다. 나머지는 **아직 가릴 수 없음**이고, 두 증거가 크게 다르면 **증거가 엇갈림**이다. 분명한 약점이 없으면 억지로 만들지 않고, 가장 낮게 나온 능력을 "시험해 볼 가설"로 주며, 그렇게 고른 능력이 맞을 비율(시뮬레이션 기준)을 함께 보여 준다. 문턱은 여섯 능력을 한꺼번에 볼 때 차이가 없는 사람의 거짓 약점이 5% 아래가 되도록 정했다. 능력마다 확실도와 증거 수를 함께 보여 준다.

**가장 비싼 습관**은 능력 사이 비교와 따로, 사용자 원인의 끊김이 만든 다시 작업(요청 100개당 분)이 가장 큰 능력이다. 같은 단위라서 능력끼리 바로 견줄 수 있고, 세션을 다시 뽑아 계산한 구간과 "가장 비쌌던 비율"을 함께 보여 준다.

결과 화면 순서: 한 줄 결론 → **가장 비싼 습관**(요청 100개당 다시 작업, 구간, 연습 하나) → **먼저 보완할 것**(이번 주에 해 볼 연습 하나 포함, 없으면 "시험해 볼 가설") → 능력 지도(전체 수준, 능력별 판정, 점수와 구간, 확실도, 과제 결과, 실제 작업의 보임·끊김) → 능력별 근거와 연습법 → 생각과 실제가 다른 곳 → 신뢰도와 한계.

만든 파일을 브라우저로 열고, 대화에는 한 줄 결론과 파일 위치만 쓴다. 결과는 평가받는 사람에게만 보여 준다.

### 8. 정리
추출본, 에피소드 표, 기회 기록, 과제, 답안, 중간 파일을 지울지 묻는다. 대화 원문과 비밀 값이 들어 있을 수 있다. 다음 진단에서 같은 주제를 다시 내지 않도록 `quizzed-topics.json`(주제 한 줄씩, 대화 원문 없음)만은 남겨 둔다.

## 한계
- 능력 정의와 과제는 이 스킬이 만든 것이고, 같은 방식으로 능력을 측정해 검증한 연구는 확인하지 못했다. 이해 퀴즈만 실제 사용자로 한 번 시험했다(`validation-notes.md`).
- 한 번 측정은 그날 컨디션을 탄다. 한두 달 간격으로 다시 재서 같은 능력이 계속 약하게 나오는지 본다. 같은 기간 길이, 같은 과제 구성일 때만 비교한다.
- 로그는 채팅 밖에서 한 일(머릿속 판단, 화면에서 직접 확인)을 담지 못한다. 그래서 로그만으로 판정하지 않는다.
- 채점은 AI의 판단이다. 채점자 둘의 일치율을 결과에 적는다. 사용자가 대화로 채점이 이상하다고 하면 그 과제를 다시 사실 확인한다.
- 판정 문턱은 지어낸 데이터로 정했다(`scripts/simulate.py`). 그 데이터에서 실제로 약한 능력에 "먼저 보완"이 붙는 비율은 증거가 보통일 때 13~24%로 낮다. 대부분은 "아직 가릴 수 없음"과 "시험해 볼 가설"로 나간다.
- 비용이 크다. 분류, 과제 생성, 검증, 채점에 에이전트를 여러 번 쓴다.

## 하지 않는 것
- 사용자에게 분류나 채점을 확인받거나, 자기 능력을 스스로 평가하게 하지 않는다.
- 다른 사람과 비교하는 점수, 등급, 기준선을 만들지 않는다.
- AI의 실수로 어긋난 장면을 사용자의 약점으로 세지 않는다.
