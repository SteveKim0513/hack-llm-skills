# 왜 이 모양인가

0.21.0까지 이 스킬은 여섯 능력의 상대 판정, 이해 퀴즈, 과제 여섯 종류, 문턱 시뮬레이션을 갖고 있었다(스크립트 9개, 약 2,700줄, 일꾼 호출 15번 이상). 문제가 나올 때마다 장치를 붙인 결과였다. 실제로 쓸 만한 결론은 하나였고, 그것은 작은 핵심에서 나왔다. 그래서 0.22.0에서 그 핵심만 남겼다. 이전 설계와 근거는 git 기록의 0.21.0에 있다.

## 남긴 것과 근거
- **어긋남은 AI가 찾고 다른 AI가 다시 따진다.** AI 분류자는 어긋남을 과하게 붙인다. 첫 실행에서 33개 중 12개, 둘째 시험에서 9개 중 3개만 재검토를 통과했다.
- **재검토를 거치면 분류자가 달라도 결과가 같았다.** 서로 다른 모델 두 분류자의 결과가 재검토 뒤 같은 습관, 같은 비용(요청 100개당 11.2분)으로 모였다(8개 세션, 요청 107개).
- **"무엇을 먼저 고칠까"는 다시 작업 시간으로 정한다.** 능력 비율은 능력마다 원래 흔한 정도가 달라 바로 견줄 수 없다. 시간은 같은 단위다.
- **승인 한마디는 증거가 아니다.** "네"로 넘어간 장면은 이해했는지 못 했는지 알려 주지 않았다(14개 중 확인 0개).

## 뺀 것과 이유
- 능력 사이 판정: 거짓 약점을 5% 아래로 막으면 실제 약점을 잡는 비율이 13~24%에 그쳐 대부분 "아직 가릴 수 없음"이었다.
- 이해 퀴즈: 지점 16개에서 검증을 거치면 3문항이 남았다. 보기형 문항은 대화를 안 본 AI가 거의 다 맞혔다.
- 과제 여섯 종류: 실제 사람에게 돌려 보지 못했고 일꾼이 가장 많이 들었다.
- "보임"과 효과 비교: 검증한 요청 뒤에 다시 작업이 더 많이 나왔다(확인하면 고칠 것을 찾는다). 인과로 읽을 수 없었다.

## 확인하지 못한 것
- 세션 40개 규모에서 같은 결과가 나오는지, 다른 사람의 기록에서도 쓸 만한지
- Codex 기록으로 끝까지 돌린 적은 없다
- 다시 작업 시간 안에 쓸모 있던 작업이 얼마나 섞이는지
