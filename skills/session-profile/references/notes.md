# 왜 이 모양인가

이전 판(0.21.0까지: 여섯 능력 판정, 과제 여섯 종류, 문턱 시뮬레이션 / 0.22.0: 가장 비싼 습관)의 설계와 근거는 git 기록에 있다. 문제가 생길 때마다 장치를 붙여 커졌던 것을 줄이고, 그동안 확인된 것만 남겼다.

## 확인된 것 (이 구성의 근거)
- **"네"만으로는 이해했는지 알 수 없다.** 짧게 승인한 장면 14개 중 이해가 확인된 것은 0개였다. 그래서 진행 요청은 기록으로 판정하지 않고 질문으로 확인한다.
- **질문은 서술형이어야 한다.** 보기형은 대화를 안 본 AI가 20문항 중 19개, 22문항 중 22개를 맞혔다. 서술형으로 바꾸자 21개 중 3개로 줄었다.
- **정답은 지금 기준이어야 한다.** 원래 세션 시점의 정답으로 채점하자, 이후 바뀐 상태를 아는 사람이 틀린 것으로 나왔다(5개 중 3개 판정이 바뀜). 그래서 질문 만들 때 이후 대화를 반영하고, 채점할 때 한 번 더 확인한다.
- **"모르겠음"은 진행 확인에서만 0점이다.** 지금 상태를 모른다는 것 자체가 이해의 증거다.
- **AI 채점자는 문제를 과하게 붙인다.** 어긋남 판정은 다시 따지면 33개 중 12개, 9개 중 3개만 남았다. 그래서 다른 채점자가 일부를 처음부터 다시 매겨 일치를 결과에 적는다.
- **바로 앞 답변에 있던 내용을 다시 묻는 장면**이 시험 실행에서 가장 분명한 약점 신호였다(문해력).
- **지문을 읽고 가린 뒤 답하는 읽기 과제는 남긴다.** 사용자가 직접 좋았다고 꼽았고, 첫 실행에서 지문 없이 쓴 답은 4점 중 1점만 맞혀 지문을 읽어야 풀리는 과제였다.

## 뺀 것
- 능력 사이의 통계적 판정(먼저 보완, 강점): 거짓 약점을 막으면 실제 약점을 거의 잡지 못했다. 대신 점수와 구간을 그대로 보여 주고, 가장 낮은 기준이 차이가 흔들림 안이면 그렇게 쓴다.
- 읽기 과제 외의 지어낸 과제(첫 메시지 쓰기, 둘 중 하나 고르기, 지시 전달, 작업 보고 받기): 사람에게 돌려 보지 못했고 만들고 검증하는 데 일꾼이 가장 많이 들었다.
- 다시 작업 시간 계산: 설득력은 있었지만 원인이 사용자인지 따지는 단계가 무거웠다.
