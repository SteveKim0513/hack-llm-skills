# criteria: 기준 기록소

사용자가 확정한 판단 기준을 파일로 남겨, 같은 질문을 반복하지 않고 답변에 반영하게 한다.
저장 형식은 `references/format.md`를 따른다. 먼저 읽는다.

## 하는 일
- **목록**: `INDEX.md`를 읽어 영역별로 보여준다. 상태(확정/초안/대체됨/폐기)를 같이 표시한다.
- **보기**: 기준 파일 하나를 보여준다. 대체 이력이 있으면 이전 버전 링크도 보여준다.
- **추가**: 사용자가 말한 기준을 그대로 적는다. 출처는 `user`.
- **변경**: 기존 파일을 덮어쓰지 않는다. 새 버전 파일을 만들고 `supersedes`로 연결하고 이전 파일은 `superseded`로 바꾼다.
- **확정**: 초안을 사용자가 승인하면 `confirmed`와 `confirmed_at`을 기록한다.
- **폐기**: 상태를 `retired`로 바꾼다. 파일은 지우지 않는다.

## 지켜야 할 규칙
- **사용자가 확정한 기준만 `confirmed`가 된다.** AI가 추정했거나 같이 만든 기준은 `draft`로 저장하고, 사용자의 명시적 동의 뒤에만 올린다.
- 기준 본문은 사용자의 표현을 최대한 그대로 둔다. 요약하며 의미를 바꾸지 않는다.
- 파일을 바꿀 때마다 `INDEX.md`를 같이 갱신한다.
- 같은 영역·결정 종류에 `confirmed`가 이미 있는데 새로 추가하라고 하면, 변경으로 처리할지 묻는다.

## 저장 전 점검 (모든 저장에 항상)
기준을 파일에 쓰기 직전에, 추가·변경·확정 어느 경로든 아래를 순서대로 스스로 점검한다. 하나라도 걸리면 저장하지 말고 고치거나 사용자에게 돌려보낸다.

1. **질문에 답하는가.** 직전에 물은 질문(영역, 결정 종류)에 이 문구가 실제로 답하는가. 다른 결정에 대한 답이면 그 부분만 저장하고, 비어 있는 부분을 "아직 비어 있음"으로 밝힌다. 예: 소스의 역할은 정했지만 "어떤 글을 사실로 인정할지"는 비어 있다.
2. **누구의 말인가.** 문구의 각 부분이 사용자가 말한 것인지 AI가 더한 것인지 가른다. AI가 더했거나 사용자가 "모르겠다"고 한 뒤 AI가 제안한 문구는 `draft`, `co-created`(또는 `ai-inferred`)로만 저장한다. "그래", "저장해"는 저장 허락이지 내용 확정이 아니다.
3. **사용자가 말한 조건이 다 들어갔는가.** 사용자가 직접 말한 제외·제약·수치(예: "광고글 제외")를 문구에서 빠뜨리지 않았는지 대화에서 다시 확인한다.
4. **나중에 판정할 수 있는가.** 결과물이 이 기준을 지켰는지 가릴 수 있는 문장인가. "균형 있게", "충분히" 같은 말은 수치·조건·예시로 구체화하거나 사용자에게 되묻는다.
5. **결정 하나인가.** 서로 다른 결정이 한 문구에 섞였으면 나눠서 따로 저장한다.
6. **확정은 따로 묻는가.** `confirmed`로 올리려면 "확정하면 다음부터 묻지 않고 이 기준대로 진행합니다. 확정할까요?"를 별도로 묻고 명시적 동의를 받는다. 저장 허락과 같은 질문에 묶지 않는다.

저장한 뒤에는 한 줄로 알린다: 무엇을 저장했는지, 상태(확정/초안), 아직 비어 있는 것.

## 저장 위치
- 프로젝트: 작업 폴더의 `.criteria/` (기본값)
- 전역: `~/.criteria/` (여러 프로젝트에 공통인 개인 취향)
- 같은 영역·결정 종류가 양쪽에 있으면 프로젝트 쪽이 우선한다.
- 위치를 사용자가 명시하지 않았으면 기본값에 저장하고, 어디에 저장했는지 한 줄로 알린다.
